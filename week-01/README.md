# Week 1 — Verify and extend Python

**Outcome:** Build a small EMIO24 inventory CLI that rejects bad input and preserves its inventory after restarting.

Think of this week as preparing a shop for business: count what you already have, decide how to handle mistakes, then create a reliable stock book.

## Your schedule

| Day | Work | Time |
| --- | --- | --- |
| 1 | Lesson 1 diagnostic, marking, targeted review | 2.5–4 hours |
| 2 | Practise only the weak topics identified by the diagnostic | 1–2 hours |
| 3 | Lesson 2: exceptions and defensive programming | 2.5–4 hours |
| 4 | Finish validation exercises and explain failures aloud | 1–2 hours |
| 5 | Lesson 3: files, CSV, JSON, persistent inventory | 2.5–4 hours |
| 6 | Finish and demonstrate the inventory CLI | 1–2 hours |
| 7 | Review evidence and revisit weak skills | Flexible |

The CLI may need extra practice time. Move forward when you can explain and demonstrate the required behaviour.

## Working rules

- Attempt Lesson 1 without the example file or review guide. It measures what you can currently do.
- For Lessons 2 and 3, use the notes and Python documentation freely. Write and explain your own code.
- Keep assignment work inside the matching assignment folder. The provided starter files are intentionally incomplete.
- Use fictional products and customers. Store monetary values as **whole naira** for this week's exercises, so ordinary integers are enough. This deliberately excludes fractional prices.
- Ask for feedback with your code, the input you used, what you expected, and what actually happened.

Run an example from the project root:

```powershell
python week-01/lesson-01/examples.py
python week-01/lesson-02/examples.py
python week-01/lesson-03/examples.py
```

The Lesson 3 example creates demonstration files in its own `demo-data` folder. Those are separate from your assignment inventory.
